Part 1 — UI/UX Blueprint

1.1 Design principles (locked before any code)

  1. A CISO gets the answer to “are we safe, and what was fixed?” within 30 seconds of opening the dashboard.
  2. Dispatch requires exactly two inputs: base URL and scenario. Everything else is auto-discovered.
  3. Status wording is fixed vocabulary and never rephrased: PATCH VERIFIED / UNPATCHED, THREAT CONFIRMED / CLEAN, VIEW PULL REQUEST, scores as n/100.
  4. Dark-only theme. No light mode in scope.
  5. Every mutating action (dispatch, clear, approve, seal) requires an API key and confirms destructive ones.

1.7 Responsive rules

  • ≥1280px: full sidebar 288px, collapsible to 80px rail with tooltips.
  • <1024px: sidebar becomes overlay drawer (max 85vw); menu button in header; overlay tap, X, and item tap all close it.
  • Metrics grid: 4 columns → 2 → 1 as viewport shrinks.
  • No overflow-hidden ancestor above dropdowns or popovers.

1.8 Accessibility and robustness

  • All icon buttons carry aria-label.
  • No clock values in the server-render path (hydration); client clocks update via effect.
  • WebSocket-first updates with polling fallback; offline shows stale banner, never fake data.
  • 401 surfaces a human message, never a blank state.

1.9 UI acceptance criteria (sign-off gate — code starts only after all pass on clickable mockups)

  1. A new user dispatches the first scenario in under 60 seconds with only base URL + scenario.
  2. Ledger row click opens the inspector with correct OWASP tag and initial-to-retest codes for all 8 vectors.
  3. PR button visible only for real http URLs; skipped state shows reason text.
  4. Mobile drawer opens and closes via menu, X, overlay tap, and item tap.
  5. Dispatch bar controls share one baseline at desktop and stack without overlap on mobile.
  6. Zero console errors; no hydration warnings.

Part 2 — Project PRD (updated)

2.1 One-liner

A B2B SaaS platform where autonomous Red Team and AI Detection Engine agents continuously attack and defend a target web application, auto-discover its attack surface from a single base URL, learn from each encounter, auto-open GitHub Pull Requests with AST-safe patches, verify them by sandbox re-test with a posted verdict comment, and produce a real-time Security Posture Score, live telemetry, and a dynamic per-operation PDF remediation roadmap.

2.2 The problem

  • Web application penetration tests are annual point-in-time snapshots, leaving months of exposure windows.
  • Red teams are expensive, scarce, and time-limited.
  • Blue teams lack realistic, continuous adversary emulation to validate web app defenses.
  • No quantitative metric exists for defense readiness that executives can track.
  • Compliance (SOC 2, ISO 27001) requires manual evidence gathering.
  • SAST/DAST scanners report without exploit validation and flood developers with false positives.
  • Naive AI patching breaks shared code (for example deleting shared Pydantic models) and causes regressions.
  • Static PDF reports and ephemeral local history cannot serve as audit evidence.

2.3 The solution: continuous purple teaming loop

Base URL + Scenario --> Auto-Recon --> Exploit --> Detection -->
AST-safe Patch PR --> Sandbox Re-test (4xx) --> PR Verdict Comment -->
Posture Score + Dynamic PDF + SARIF

Key innovation: adversarial learning with a safe auto-remediation loop. The Red Agent probes the base URL to discover real endpoints (route probing plus HTML form and input crawling), then exploits. The AI Detection Engine analyzes logs and requests, decides the response alone, generates a minimal patch preserving shared models, opens an isolated patch/<vector>-xxxxxx branch and Pull Request via the GitHub REST API (no git clone on the server), and re-verifies by sandbox re-test with the verdict posted on the PR. Past encounters are reused via RAG context, enabling measurable improvement.

2.7 Why this project stands out

  • Adversarial learning loop: Red and Blue co-evolution, not static scans.
  • Zero-input recon: only the base URL is entered; sub-paths are auto-discovered.
  • Git-native auto-PR: real patch branches and PRs, not in-memory edits.
  • Regression-free patching: AST-aware, shared models preserved, strict input rejection.
  • Quantitative posture: executive metric plus live observability.
  • Fully autonomous Blue side: no human in the detect, patch, and verify loop.
  • Safe sandbox: isolated container with per-episode reset.
  • Standards-native: OWASP Top 10 plus MITRE ATT&CK mapping, SARIF export, tamper-evident seals.
  • Live compliance: dynamic per-run PDF, persistent audit ledger, green CI.

2.8 Customers and business model

CISO, VP Security, AppSec Lead, Audit and Compliance. Mid-market to Enterprise. Tiered SaaS per application plus Enterprise annual. Go-to-market via AppSec community, cyber-insurance partnerships, and CI/CD marketplace.

Diminishing returnsPlateau reported honestly after the first 5 to 10 episodes.

2.10 Success metrics

  • Detection rate: at least 85 percent on known scenarios (8 vectors).
  • Patch acceptance: PRs passing CI and re-test without manual fix.
  • MTTR: discovery to verified PR, in minutes of wall-clock time.
  • Regression incidence: near zero (no NameError or build failure).
  • Episode duration: at most 30 minutes (seconds in demo: 200 to 403).
  • Demo: all 8 web scenarios with measurable posture gain across the first 5 to 10 episodes.

2.11 Build order

  1. One scenario end-to-end (1 Red plus 1 Blue) with auto-recon.
  2. Second Red plus second Blue on the same scenario (detect and harden split).
  3. Expand to 8 scenarios with uniform WAF and re-test pattern.
  4. Git-native PR, verdict comment, dynamic PDF, WebSocket.
  5. Postgres persistence, Prometheus and Grafana, CI, mobile spec, trust surface.
  6. Planned: Neo4j hybrid Graph-RAG, Flutter client.

2.12 Cost profile

Free-first: Groq free tier, Railway trial or free plus Vercel Hobby, free Postgres, open-source ChromaDB, Docker, and Next.js. Compute, hosting, and development time are real costs; licensing is free.
