Mirsad — UI/UX Blueprint

Autonomous Purple Team Platform · interface-first blueprint (companion: project PRD)

Version 1.0  |  Status: proposed — no implementation code is authorized until every screen below is signed off  |  All content in English

1. Design principles (locked before any code)

  1. A CISO will get the answer to “are we safe, and what was fixed?” within 30 seconds of opening the dashboard.
  2. Dispatch will require exactly two inputs: base URL and scenario. Everything else will be auto-discovered.
  3. Status wording will be fixed vocabulary and never rephrased: PATCH VERIFIED / UNPATCHED, THREAT CONFIRMED / CLEAN, VIEW PULL REQUEST, scores as n/100.
  4. Dark-only theme. No light mode will be in scope.
  5. Every mutating action (dispatch, clear, approve, seal) will require an API key, and destructive ones will confirm first.

7. Responsive rules

  • ≥1280px: full sidebar 288px, collapsible to 80px rail with tooltips.
  • <1024px: sidebar becomes overlay drawer (max 85vw); menu button in header; overlay tap, X, and item tap all close it.
  • Metrics grid: 4 columns, then 2, then 1 as the viewport shrinks.
  • No overflow-hidden ancestor above dropdowns or popovers.

8. Accessibility and robustness

  • All icon buttons will carry aria-label.
  • No clock values in the server-render path (hydration); client clocks will update via effect.
  • WebSocket-first updates with polling fallback; offline will show a stale banner, never fake data.
  • 401 will surface a human message, never a blank state.

9. UI acceptance criteria (sign-off gate — implementation starts only after all pass on clickable mockups)

  1. A new user will dispatch the first scenario in under 60 seconds with only base URL plus scenario.
  2. A ledger row click will open the inspector with the correct OWASP tag and initial-to-retest codes for all 8 vectors.
  3. The PR button will be visible only for real http URLs; the skipped state will show reason text.
  4. The mobile drawer will open and close via menu, X, overlay tap, and item tap.
  5. Dispatch bar controls will share one baseline at desktop and stack without overlap on mobile.
  6. Zero console errors and no hydration warnings.
